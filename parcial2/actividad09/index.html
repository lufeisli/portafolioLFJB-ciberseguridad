Actividad 9: LABORATORIO ESPECIALIZADO · PATH TRAVERSAL

Stripped Non-Recursively: reconstruyendo el traversal

Práctica de laboratorio especializado sobre el reto "File path traversal, traversal sequences stripped non-recursively" de PortSwigger Web Security Academy (nivel Practitioner).


La aplicación elimina las secuencias ../ del parámetro, pero solo en una pasada. Este informe documenta cómo se construyó un payload que, tras esa única eliminación, reconstruye la secuencia de traversal y permite leer /etc/passwd.

Preparación del Laboratorio

El laboratorio es de nivel Practitioner y contiene una vulnerabilidad de path traversal en la visualización de imágenes de producto de "We Like To Shop". La aplicación elimina las secuencias ../ del nombre de archivo, pero en una sola pasada no recursiva, antes de usarlo. El objetivo es recuperar /etc/passwd.

Fig 1: Descripción del laboratorio "Traversal sequences stripped non-recursively"

Concepto Teórico: filtrado no recursivo
Un filtro no recursivo elimina un patrón en una única pasada. Si tras eliminar una ocurrencia los caracteres restantes se recombinan formando una nueva ocurrencia, esta ya no vuelve a examinarse. Un filtro correcto debe repetirse hasta alcanzar un punto fijo.

Fase 2: Construcción del Payload

Se envió una petición a Repeater y se construyó un payload diseñado para evadir un filtro de una sola pasada:

# Payload que reconstruye ../ tras el filtrado
GET /image?filename=....//....//....//etc/passwd HTTP/2

Fig 4: Envío de la petición a Burp Repeater

Fig 5: Petición original filename=29.jpg en Repeater

Concepto Teórico: bypass de filtros de una sola pasada
Al escribir ....//, el filtro detecta y elimina los tres caracteres centrales que coinciden con ../, pero los caracteres restantes se recombinan en una nueva secuencia ../ válida. Repetido varias veces, el resultado tras el filtrado es ../../../.

Fase 3: Explotación y Confirmación

Al enviar la petición modificada, el servidor respondió con el contenido íntegro de /etc/passwd, confirmando la evasión del filtro.

Conclusiones y Mitigación

El patrón ....// es suficiente para evadir un filtro que no se aplica de forma iterativa. Recomendaciones principales:

  • Aplicar la eliminación de ../ de forma recursiva, repitiendo hasta que una pasada no produzca cambios.
  • Preferir rechazar la entrada sospechosa en vez de intentar sanearla o reescribirla.
  • Resolver la ruta a su forma canónica y verificar que quede dentro del directorio base permitido.
  • Sustituir filename por un identificador indirecto validado contra una lista de archivos permitidos.
